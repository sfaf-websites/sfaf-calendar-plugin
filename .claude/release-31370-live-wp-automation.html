Trigger DISABLE_WP_CRON is not set, so WordPress is still firing scheduled tasks off visitor traffic. That means a 6am reminder does not go out until somebody visits the site. Set up the external ping first and confirm above that tasks are running, then add the constant. Doing it the other way round can leave nothing running at all. The readme has the steps in order.
Cron URL https://resources.sfaf.orgwp-cron.php?doing_wp_cron
This is the address an external scheduler should request, every 15 minutes. It needs no parameter, no header and no key, and it keeps working once DISABLE_WP_CRON is set. Do not point the scheduler at the page-view nudge below instead: that one runs this plugin's jobs only, and would leave the rest of WordPress's schedule stopped.
Page-view nudge No page has started a run yet. Every sfaf.org page with a calendar on it asks this site to run its jobs, at most once every 15 minutes. Nothing is set up for this and nothing needs to be. Leave it on after the external scheduler is working: it is a request from a site that has visitors, which is what lets this site notice the scheduler has stopped and send the alert email below.
