▼

Default 12. Use 0 or -1 to show all events with no pagination. Override per shortcode with per_page="20".

The page that carries the calendar. Event pages are served from this site and the calendar usually is not, so this is where All Events and the category chips on an event page send somebody who arrived without a referrer: a shared link, a search result, a bookmark. When they did click through from a calendar, they go back to that exact page instead, whichever one it was.
If there are several calendar pages, this one is the fallback for all of them. The plugin cannot tell which page holds a shortcode and does not try to guess. Leaving this empty falls back to this site's own event archive, which is almost certainly not what a visitor should be shown.

Scheduled Tasks

The hourly runner: morning-of reminders, and automated fetching

WP pseudo-cron ▼

Status: The scheduled run has never completed yet. If you have just installed this, wait for the top of the hour or press "Run now". The full run log and a “Run now” button are on the Automation screen.

WordPress is still firing scheduled tasks off visitor traffic. That means a 6:00am reminder does not go out until somebody happens to visit the site. Add a system cron job hitting https://resources.sfaf.orgwp-cron.php?doing_wp_cron hourly, and set define( 'DISABLE_WP_CRON', true ); in wp-config.php. The readme has the exact steps.

Send morning-of reminders 6:00am site time on the day of the event, to everyone registered plus the event's notification list. Native events only: imported events are never sent for, because their platform sends its own.
Fetch from third-party sources automatically Leave this off for now. A fetch can take an event off the calendar when it stops being returned by its source, and that behavior has never been watched through a real removal. Running it unattended before then is how live events disappear overnight. Switch it on by hand once one removal has been seen go through correctly. “Fetch updates” on the dashboard runs it manually in the meantime.

Failure alerts

An admin notice only works on somebody who is logged in and looking, which is exactly what nobody is doing at 3am. These two conditions are also emailed: three failed runs in a row, and no completed run for three hours. You get one message when it breaks, at most one a day while it stays broken, and one when it starts working again. Separate from the event email settings on purpose: this is about the server, not about the events.

Leave blank to use this site's administration email (). Alerts currently go to nobody.

Google Maps

An optional map on the event page.

Not configured ▼

Paste a key and every event page with an address shows a map, loaded from Google when the visitor reaches it. Google is told the page was viewed, and event pages cover HIV services, substance use, and trans health programming. Leave this blank and the page shows the address as an ordinary Google Maps link alone, with no map and no error.

Restrict the key before you paste it in. In the Google Cloud console set Application restrictions to HTTP referrers and list both resources.sfaf.org/* and sfaf.org/*, then set API restrictions to the Maps Embed API and nothing else. The Embed API has no usage cap, so an unrestricted key is a billing exposure rather than a map risk: anyone who copies it can run it up on their own site against this account.

Cloudflare Turnstile

Spam protection for the public event submission form.

Not configured ▼

Both keys, or the widget does not appear at all. A site key with no secret would draw a checkbox that nothing verifies. Use the same Cloudflare account and domain that Gravity Forms already uses on this site.

This protects the community submission form at uc_event_submit=, which has no login and no email check. The staff request form does not use it: a link sent to an sfaf.org mailbox is already a stronger check. If Cloudflare cannot be reached the submission still goes through, and the honeypot, the rate limits and the pending queue still apply.

GoFundMe Pro

Manage campaigns and display live progress on event cards

Active ▼

GoFundMe Pro uses OAuth2 (client credentials). Tokens and data come from different hosts. GoFundMe Pro support has confirmed the token endpoint below is correct, so leave it as it is; pro.gofundme.com does not issue tokens. Every request also carries the x-integration-id header they issued, which is what stops their edge security treating this server as a bot.

Leave blank to use the defaults shown. In use now. Token: https://api.classy.org/oauth2/auth · data: https://pro.gofundme.com/api/2.0 · integration ID: NSINTG4F8A2C9D6Q1

The Organization ID is not used to obtain a token. It identifies which organization's data to read, in calls such as GET /organizations/{org_id}/campaigns. Set it before the campaign step.
