Embed width probe

Each mode is measured on its own, in three kinds of parent. A block parent takes its width from the page; a table cell and a flex item take theirs from their contents, which is the case that broke in 3.24.0 and the case nothing was testing.

THE TWO MODES ARE MEASURED IN SEPARATE CELLS ON PURPOSE. The first version of this page put a sidebar and a list card in the same cell, and in the table and flex sections every column came out at 260px whatever it had been asked for: the list card's own 260px min-width was setting the floor and the sidebar beside it was never the thing being measured. One mode per cell, or the number belongs to the other one.

Combined mode: where it stacks

The month grid and the list side by side. Flex line breaking uses each item's flex-basis, so the arithmetic says 576 + 320 + 24 = 920px and this pins it: the row above 920 should report side by side and the row below it stacked. Measured rather than calculated, for the reason the sidebar minimum was: 3.24.0 published a number it had worked out and the number was 30px wrong.

AND WHETHER THE GRID STILL SHOWS ITS EVENTS, which is the column added in 3.31.1. Side by side is only worth having if the grid gets a column it can use: under 560px of its own width it collapses to seven columns of dots, and stacking at the same page width would have given it everything. The 400px basis shipped in 3.30.0 put the changeover at 744px and left the grid in dot mode all the way to 1064px, which is what a 770px page on sfaf.org was showing.
